# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Balanced by Daylight (a.k.a. DBD Balance Checker): a Node/Express + Pug web app that lets competitive Dead by Daylight players build loadouts and validate them against tournament-league balancing rulesets. Pure vanilla JS on the client (no framework); server renders Pug views and exposes image-generation / OCR / autobalance APIs.

## Running the app

```bash
npm i                              # install deps (canvas, sharp, tesseract.js compile native bits — needs build tools)
node server.js --disable-autobalance   # <-- normal local dev command
npm start                          # = `node server.js`; ONLY works if you have a valid .env (autobalance access)
```

- The server listens on **http://localhost:3000**.
- `autobalancer.js` calls `dotenv.config()` and reads Google service-account creds + `AUTOBALANCE-KEYS` at import time. Without a `.env`, plain `node server.js` crashes. The `--disable-autobalance` flag short-circuits all Google Sheets logic and writes a default `public/Balancings.json` pointing at the `DEBUG` preset — use it for essentially all local work.
- **No test suite exists.** `npm test` deliberately exits with an error. Verify changes by running the server and exercising the UI in a browser.

## Generated / gitignored runtime files

Several files the running app depends on are NOT in git (see `.gitignore`) and are produced at startup or by tooling:
- `public/Balancings.json` — the preset index the client fetches first. Generated by `autobalancer.js` (default DEBUG entry under `--disable-autobalance`, or the full league list otherwise). If it's missing, the checker page can't load.
- `public/BalancingPresets/Autobalance/*` — league presets fetched from Google Sheets / GitHub at runtime.
- `.env`, `autobalance-info/*` — autobalancer secrets and per-league state.

## Architecture

### Server (`server.js`)
Express + Socket.io on port 3000, Pug view engine, `public/` served statically. Key endpoints:
- `routes/viewRoutes.js` — renders `/` (index), `/balance-creator`, `/balance-checker`.
- `POST /get-build-image` → `canvasGenerator.js` (renders a PNG of a loadout).
- `POST /image-extractor` (multer upload) → `imageExtractor.js` (OCR + pixel-match a screenshot back into build data).
- `GET /imageProxy` — proxies external (Discord) images.
- `GET /config` — returns `server-config.json` (`multiplayerEnabled`, `saveBuilds`).
- Socket.io multiplayer rooms are only wired up when `server-config.json` has `multiplayerEnabled: true` (currently false).

### Autobalancer (`autobalancer.js` + `autobalance-api.js`)
Polls a Google Sheet (via `google-spreadsheet`) listing leagues, fetches each league's balancing JSON (from GitHub or a custom URL), optionally runs a converter, and writes it under `public/BalancingPresets/Autobalance/`. `autobalance-api.js` exposes `/autobalance/...` routes guarded by an API key from the `AUTOBALANCE-KEYS` env var. Requires `.env` (`AUTOBALANCE_ENABLED`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `AUTOBALANCE-KEYS`).

### Client (`public/scripts/checker/`)
Vanilla JS, loaded in a **fixed order** by `views/balance-checker.pug`. Order matters — globals/utilities must load before consumers:
`checker-globals.js` → `checker-constants.js` → `checker-utility.js` → `checker-modal.js` → `checker-search.js` → `checker-events.js` → `checker-error-validation.js` → `checker-frontend.js` → `checker-resources.js` → `checker-main.js`.

- **Boot:** `<body onload="BeginResourceChain()">` (`checker-resources.js`) runs a **synchronous** XHR chain — `Balancings.json` → `Perks/dbdperks.json` → `Killers.json` → `Survivors.json` → `NewMaps.json` → `NewAddons.json` → `Items.json` → `Offerings.json` — then calls `main()` in `checker-main.js`.
- **Preset loading is lazy:** `Balancings.json` holds metadata only; a preset's `Balancing` object is fetched on demand from its `Path` via `GetBalancingFromPresetID()`.
- **Build state** lives in mutable globals in `checker-globals.js`: `SurvivorPerks[4][4]`, `SurvivorItems[4]`, `SurvivorAddons[4][2]`, `SurvivorOfferings[4]`, `KillerPerks[4]`, `KillerAddons[2]`, `KillerOffering`, plus `selectedRole` (0=survivor,1=killer), `selectedKiller`, `currentBalancingIndex`, `customBalanceOverride`. Optionally persisted to `localStorage`.
- **Validation** is entirely client-side. `checker-error-validation.js` (with helpers in `checker-utility.js`) pushes to the global `MasterErrorList` — checks perk repetition (`MaxPerkRepetition`), in-build duplicates, individual & combo perk bans (per `Tiers` and per-killer `KillerOverride`), addon-tier/item/offering whitelists, etc.
- `public/scripts/balance-creator.js` is the standalone editor for authoring these preset JSON objects.

### Balancing preset shape
Validated by `ValidateCustomBalancing()`. Top level: `Name`, `MaxPerkRepetition`, `GlobalNotes`, `Tiers[]` (each with Survivor/Killer Indv/Combo perk bans), and `KillerOverride[]` (per-killer bans, whitelists, addon tiers, offerings, `AntiFacecampPermitted`, notes). Perks/items/addons are referenced by **ID**, not name.

### Image generation vs. WebP
The live site uses `.webp` assets in `public/`. **node-canvas cannot read WebP**, so `canvasGenerator.js` and `imageExtractor.js` read PNG mirrors from `canvas-image-library/` instead. When adding/renaming assets, update **both** the WebP set in `public/` and the PNG set in `canvas-image-library/`.

### Game data files (`public/`)
`Killers.json`, `Perks/dbdperks.json`, `Survivors.json`, `Items.json`, `NewAddons.json`, `NewMaps.json`, `Offerings.json`. Note the active map/addon files are the `New*` variants; `Old*` files are legacy inputs for the converters.

## Tooling (`utilities/`, root scripts)
Standalone scripts run directly, not part of the server. Node tools: `node <script>.js`; Python tools: `python <script>.py`. Their `input/`/`output/` dirs are gitignored.
- `utilities/addon-combine-tool` — layer addon icons onto rarity borders (also has a character-matching mode).
- `utilities/{killers,addon,map}-format-converter` — convert legacy `Old*`/`Legacy*` JSON to the `New*` formats the app consumes.
- `utilities/{hue-shift-tool,image-crop-tool,image-resizer}` — batch image processing (sharp / node-canvas).
- `utilities/autobalancer/autobalancer-dbdl.js` — league-specific balance-format converter (uses `natural`/Jaro-Winkler fuzzy name matching). Currently commented out in `autobalancer.js`.
- `utilities/build-sheet-generator` — renders PNG sheets of specific killer/survivor builds actually played (not allow-lists), with an optional `--rules` check against an allow-list YAML. Unlike the other tools it is also a **standalone npm package** usable outside this repo (`npm i ./utilities/build-sheet-generator`, bin `dbd-build-sheet`, or `require('dbd-build-sheet-generator')`): it resolves its asset root and loads game data per run rather than at module load, `fatal()` throws a `BuildSheetError` instead of calling `process.exit`, and the CLI only runs under `require.main === module`. The artwork is never bundled — an outside caller points it at a checkout with `--asset-root`, the `assetRoot` option, or `DBD_BALANCING_TOOL_ROOT`.
- `png_to_webp/`, `webp_to_png/` (Pillow), `name_conversion/` — asset filename/format normalization helpers.

## Conventions
- Asset filenames use dashes for spaces and underscores for apostrophes/periods (see `name_conversion`); image `src`/icon paths in JSON must match exactly.
- `UpdateLog.md` is the user-facing changelog; `ExtendedChanges.txt` is for longer per-commit explanations.
